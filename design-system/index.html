One language for every transaction.

Typography

Onest carries the product. Geist Mono is reserved for codes and aligned numbers. Page headings are 24/30 at medium weight; section titles and long-form reading copy are 16/24. Chat and message bodies use 15px. Every button, select, input and textarea uses the same 14px control text size as Ask Sofia. Comfortable mode raises controls to 16px and both messages and reading copy to 18px.

Layout and accessibility contract

Scan first, act next.The product rail is 56px, contextual panel 272px, content starts on one shared page rail. Dense comparison becomes a readable stack by container width. Every screen must work with keyboard focus, 200% zoom, 44px touch targets on touch devices, and reduced motion.

Control shape and target

Use 36px default buttons, 40px fields and at least 44px targets on touch. Compact size does not make a touch target smaller. Radius follows role rather than taste.

Alignment test

Before approving a component, check all nine properties together: font-size, font-family, color, padding, gap, border, border-radius, align-items and justify-content. The visible text, icon and chevron form one group; date and description share a baseline; headers and data share a column grid. If text collides, adapt width or wrap—never fix it with negative margins.

Contrast:Meaningful text, including placeholders, must reach at least 4.5:1 on the actual surface. Risk and completion require a text label as well as color.

04

States and accessibility

A component is not finished when its default screenshot looks correct. These states are part of the reusable component; the full matrix covers semantics and interaction requirements.

StateVisual evidenceInteraction / semantics
DefaultClear hierarchy and readable nameAccessible name matches visible purpose.
Hover / focusQuiet hover; 2px focus ring with 3px offsetKeyboard focus follows reading order; hover is not the only affordance.
Selected / pressedWhite tab surface or distinct selected surfacearia-selected, aria-pressed or current-page state is accurate.
Disabled / loadingStable geometry, unambiguous unavailable/progress stateNo duplicate submission; disabled control cannot act.
Error / successText plus color, adjacent to affected contextError is associated with its field; success is announced where needed.
Empty / long / zoomNext step visible; text wraps without collision or clippingFull value available at 200% zoom and Comfortable type.

Do

Keep the label and the reason together: “Offer expires · 2 days overdue.” Preserve the editable value after validation. Let a drawer scroll all the way to its final action.

Do not

Use color alone for risk, repeat an approval action in two places, shrink the target to fit a label, nest an input border inside a search shell, or hide the last list row under clipped bottom padding.

Patterns

These compositions solve repeatable ZipQ jobs. They are more binding than a screenshot: behavior, spacing, and state vocabulary travel together.

Priority work

Agenda groups Overdue → Today → This week → Later. The active view is in the header; the list shows no duplicate uppercase group labels. Suggestion bar spans the same rail as its cards.

One main work column and one contextual rail. Tasks, checklist and key dates disclose details inline; counts sit next to arrows. The entire detail scrolls, including long documents and log content.

Overlay keeps the client list behind it. Four actions use the shared 14px action label with 44px targets and stay on one line where space permits. Communication by channel

Chat is the aggregate view. Email reads like an email, SMS like a two-party message, Calls show start/end/duration, and DocuSign shows recipient signatures as verified states.

src/50-txdetail.js · channelView() · .channel-*

Sofia proposes, you approve

Separate extracted facts, suggestions, drafts and committed changes. Do not imply that AI has saved or sent consequential work before the user confirms. No prompt chips below the ongoing conversation.

src/35-sofia.js · .chat-confirm-reply · .act-card

Forms and playbook

Template cards show name, purpose, form codes and at most two representative work items. Use 24px outer padding, 16px between major groups, 12px inside Work items and 32px-tall preview rows. The reuse banner keeps 16px padding on every side. Work item, Due, Owner and Reminder stay on one aligned grid until the component itself is constrained; every group arrow opens and closes its rows.

src/50-txdetail.js · src/65-forms.js · .template-card · .template-assist · .form-disclosure-button · .playbook-work-items

Search and command

One global Search in the sidebar. ⌘K opens only Search. The input has one border, one focus treatment, and a result grouping with clear empty state.

src/20-shell.js · .sidebar-search · .search-box

Readable operations

Use 16px for long-form reading copy and 15px for chat/message bodies; every text-bearing button, input, select and textarea uses 14px like Ask Sofia. Settings offers 18px messages and reading copy/16px controls in Comfortable mode. Risk uses a label plus color; focus and touch targets remain visible.

07

Implementation rules

The agent handoff lives at the repository root. Both humans and agents must follow CONTRACT.md and SPEC.md before touching product UI.

Reuse before creating

Search the component inventory and existing classes first. Extend a shared primitive when an intent repeats; do not create a visually similar one-off control.

rg -n "ui-button|ui-input|data-grid|agenda-flat-row" src

Verify before shipping

Build, run DOM regression checks, check contrast and review the changed layout at narrow, regular and comfortable-text sizes. Record any live-browser verification limit honestly.

node build.mjs node scripts/check-design-system.mjs git diff --check

Extend the system, not one screen

When intent repeats, update its token or primitive and migrate every occurrence. A new component needs anatomy, variants, states, keyboard behavior, responsive rules, source owner and a catalog example.

Foundations → Component → Pattern → Screen

Review the whole state space

Inspect default, hover, focus, selected, disabled, loading, error, empty and long-content states. Check desktop, constrained drawer, mobile, Comfortable type and 200% zoom. A passing build does not prove visual parity.

node scripts/check-ui-regressions.mjs

Known constraintThis catalog is built from the checked-in CSS and source components. It does not claim pixel verification of every historical screenshot. See ACCESSIBILITY-AUDIT.md and FEEDBACK-AUDIT.md for evidence and unresolved verification limits.
